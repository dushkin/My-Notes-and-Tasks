# Frontend Agent Guidelines - NoTask

**Role**: Implement React UI, components, hooks, client-side logic, and mobile features
**Never touch**: Backend code, MongoDB models, Express routes, server-side Socket.IO

## Tech Stack

- **Framework**: React 18 with Vite
- **Styling**: TailwindCSS with custom theme
- **Editor**: TipTap rich text editor (v2)
- **Routing**: React Router DOM v7
- **State Management**: React hooks + Context API
- **Real-time**: Socket.IO client
- **Mobile**: Capacitor 7 for Android
- **Testing**: Playwright (E2E) + Jest + React Testing Library

## Key Components

### Tree Management ([src/hooks/useTree.jsx](src/hooks/useTree.jsx))

**Responsibilities**:
- Maintain tree state in memory
- CRUD operations on items (create, update, delete, move)
- Undo/redo history
- Sync with backend via API
- Handle Socket.IO real-time updates

**Critical Rules**:
- All tree mutations must call backend API first
- On success, update local state optimistically
- On error, revert changes and refetch from server
- Tree operations must broadcast via Socket.IO for multi-client sync

**localStorage Handling**:
```javascript
// Large trees (>5MB) exceed localStorage quota
try {
  localStorage.setItem('cached_tree_data', JSON.stringify(tree));
} catch (error) {
  if (error.name === 'QuotaExceededError') {
    console.warn('⚠️ Tree too large, using memory only');
    window.treeData = tree; // Fallback for reminder monitor
  }
}
```

### TipTap Editor ([src/components/editor/](src/components/editor/))

**Features**:
- Rich text formatting (bold, italic, lists, etc.)
- RTL/LTR direction support
- Auto-save on blur
- Content sanitization before saving

**Anti-patterns**:
- ❌ Don't set content directly - use TipTap commands
- ❌ Don't bypass sanitization - always sanitize HTML
- ✅ Use `editor.commands.setContent()` for updates
- ✅ Validate content before API calls

### Socket.IO Client ([src/hooks/useSocket.jsx](src/hooks/useSocket.jsx))

**Events to Handle**:
- `tree_updated` - Another client modified tree
- `item_created` - New item added
- `item_updated` - Item modified (label, content, etc.)
- `item_deleted` - Item removed
- `item_moved` - Item repositioned

**Connection Management**:
```javascript
// Always include JWT token in auth
const socket = io(API_BASE_URL, {
  auth: { token: localStorage.getItem('token') }
});

// Reconnect logic on token refresh
socket.on('connect_error', () => {
  // Refresh token and reconnect
});
```

### Authentication ([src/hooks/useAuth.jsx](src/hooks/useAuth.jsx))

**Flow**:
1. User logs in → Store JWT + refresh token
2. API requests include `Authorization: Bearer <token>`
3. On 401 error → Attempt refresh token
4. On refresh success → Retry original request
5. On refresh failure → Redirect to login

**Token Storage**:
```javascript
localStorage.setItem('token', accessToken);
localStorage.setItem('refreshToken', refreshToken);
```

## API Communication

### Base URL
```javascript
const API_BASE_URL = import.meta.env.VITE_API_BASE_URL;
// Dev: https://my-notes-and-tasks-backend-dev.onrender.com
// Prod: https://my-notes-and-tasks-backend.onrender.com
```

### Authenticated Requests ([src/services/api.js](src/services/api.js))

```javascript
const authFetch = async (endpoint, options = {}) => {
  const token = localStorage.getItem('token');

  const response = await fetch(`${API_BASE_URL}${endpoint}`, {
    ...options,
    headers: {
      'Content-Type': 'application/json',
      'Authorization': `Bearer ${token}`,
      ...options.headers
    }
  });

  if (response.status === 401) {
    // Attempt token refresh
    const refreshed = await refreshAccessToken();
    if (refreshed) {
      // Retry original request
      return authFetch(endpoint, options);
    } else {
      // Redirect to login
      window.location.href = '/login';
    }
  }

  return response.json();
};
```

### Error Handling

```javascript
try {
  const result = await authFetch('/items', { method: 'POST', body: data });
  return { success: true, data: result };
} catch (error) {
  console.error('API error:', error);
  showNotification(error.message, 'error');
  return { success: false, error: error.message };
}
```

## State Management Patterns

### Tree State (useTree hook)

```javascript
const [tree, setTree] = useState([]);
const [expandedFolders, setExpandedFolders] = useState(new Set());
const [selectedItem, setSelectedItem] = useState(null);
const [history, setHistory] = useState({ past: [], future: [] });
```

**Update Pattern**:
```javascript
// 1. Optimistic update
const newTree = mapRecursive(tree, itemId, updateFn);
setTreeWithUndo(newTree);

// 2. API call
try {
  const updated = await authFetch(`/items/${itemId}`, {
    method: 'PATCH',
    body: JSON.stringify(updates)
  });

  // 3. Sync with server response
  const syncedTree = mapRecursive(tree, itemId, () => updated);
  setTree(syncedTree);
} catch (error) {
  // 4. Revert on error
  undo();
  fetchUserTree(); // Full refetch as fallback
}
```

### Undo/Redo

```javascript
const setTreeWithUndo = useCallback((newTree) => {
  setHistory(prev => ({
    past: [...prev.past, tree],
    future: []  // Clear redo stack on new change
  }));
  setTree(newTree);
}, [tree]);

const undo = useCallback(() => {
  if (history.past.length === 0) return;
  const previous = history.past[history.past.length - 1];
  setHistory(prev => ({
    past: prev.past.slice(0, -1),
    future: [tree, ...prev.future]
  }));
  setTree(previous);
}, [history, tree]);
```

```javascript
// Lazy load heavy components
const Editor = lazy(() => import('./components/editor/TipTapEditor'));

<Suspense fallback={<Loading />}>
  <Editor content={content} />

```

### Memoization

```javascript
// Expensive computations
const sortedTree = useMemo(() => {
  return sortItems(tree, sortBy);
}, [tree, sortBy]);

// Callbacks to prevent re-renders
const handleUpdate = useCallback((id, data) => {
  updateItem(id, data);
}, [updateItem]);
```

## Common Pitfalls

⚠️ **localStorage Quota**: Large trees exceed 5-10MB limit - gracefully fallback to memory only
⚠️ **Socket.IO Auth**: Always include JWT token in connection auth
⚠️ **TipTap Content**: Use `.setContent()` not direct DOM manipulation
⚠️ **Capacitor Sync**: Run `npx cap sync` after plugin changes or build will fail
⚠️ **Mobile Testing**: Browser dev tools != actual device behavior
⚠️ **Optimistic Updates**: Always have revert/refetch fallback on API errors

## Questions to Ask Backend Agent

When implementing features that touch backend:
- What's the API endpoint signature?
- What validation happens server-side?
- What events should be emitted via Socket.IO?
- What's the expected response format?

## Handoff to Other Agents

**To Backend Agent**: Provide API requirements (endpoint, method, payload, response)
**To Mobile Agent**: Specify native features needed (notifications, file access, etc.)
**To Testing Agent**: List E2E flows to cover
**To Performance Agent**: Share bundle analysis results for optimization

**Remember**: Focus on UI/UX and client-side logic. Leave backend concerns to Backend Agent. Coordinate real-time events with Real-time Agent.
